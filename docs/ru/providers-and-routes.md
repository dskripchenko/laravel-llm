# Провайдеры и маршруты

## Провайдеры (`llm_providers`)

| Колонка | |
|---|---|
| `name` | уникальное, показывается в журнале |
| `base_url` | корень OpenAI-совместимого API, **включая `/v1`**: `http://127.0.0.1:11434/v1` (Ollama), `http://host:8000/v1` (vLLM), `http://127.0.0.1:1234/v1` (LM Studio), `http://127.0.0.1:8080/v1` (llama.cpp server) |
| `api_key` | необязательный; шифруется ключом приложения; передаётся как `Authorization: Bearer` |
| `models` | справочный список моделей, которые обслуживает провайдер (для админки) |
| `limits` | `timeout` (секунды, переопределяет `llm.http.timeout`), `max_output_tokens` (ограничивает `max_tokens` каждого запроса) |
| `is_cloud` | провайдер находится вне инфраструктуры арендатора |
| `cloud_enabled` | администратор разрешил облачного провайдера |
| `is_enabled` | отключённый провайдер пропускается |
| `attribution` | принимает «чей вызов» заголовками (шлюз, который ведёт по ним свой учёт); по умолчанию false |
| `prices` | по модели или `*` для любой: `{"input": 3, "output": 15}` за миллион токенов; по ним считается `cost` в журнале |

### Облачные провайдеры

> **Внимание.** Промпт содержит данные арендатора — статьи, комментарии,
> сообщения. Отправка его в облачный API выводит эти данные за пределы
> инфраструктуры арендатора. Поэтому пакет никогда не направляет запросы
> провайдеру с `is_cloud = true`, если не установлено ещё и
> `cloud_enabled = true`. Открывайте `cloud_enabled` только администраторам,
> которые вправе принять такое решение, и помечайте каждую нелокальную
> точку доступа как `is_cloud`: пакет не может определить, куда ведёт URL.

Отклонённый облачный маршрут пропускается (с предупреждением в журнале
приложения), и пробуется его резервный маршрут; если не осталось ничего,
выбрасывается `CloudProviderNotEnabled` и ничего не отправляется.

### Чей вызов и стоимость

Вызов может сказать, от чьего имени он сделан и к какой работе относится:

```php
Llm::prompt(SummarizeArticle::class, ['article' => $text])
    ->onBehalfOf($user->external_id)           // идентификатор человека или агента у провайдера входа
    ->attribute(project: 'KB', task: 'KB-12', run: 'run-7')
    ->run();

Llm::embed($texts, attribution: new Attribution(onBehalfOf: 'agent-7'));
```

В журнале вызовов это хранится всегда (`on_behalf_of`, `attribution`).
Отправляется — только провайдеру с `attribution = true`, заголовками
`X-On-Behalf-Of`, `X-Project`, `X-Task` и `X-Run`
(`llm.attribution.headers`): шлюз перед моделями ведёт по ним свой учёт и
дальше их не передаёт. Любой другой провайдер — прежде всего облачный —
их не получает.

`cost` в журнале — то, что сказал ответ провайдера (`usage.cost`), иначе
то, что дают токены по `prices` провайдера; null, если неизвестно ни то,
ни другое.

## Маршруты (`llm_routes`)

Маршрут сопоставляет **назначение** — `chat`, `summarize`, `classify`,
`extract`, `embed`, `rerank` (`Dskripchenko\Llm\Purpose`) — провайдеру
и модели.

| Колонка | |
|---|---|
| `purpose` | |
| `scenario` | необязательно: маршрут только для одного сценария (например, `wiki.answer`); если маршрута для сценария нет, используется маршрут назначения |
| `provider_id`, `model` | |
| `fallback_route_id` | маршрут, который пробуется, когда этот недоступен |
| `options` | опции запроса по умолчанию для этой модели (`temperature`, `num_ctx`…); опции промпта или вызывающего кода их переопределяют |
| `is_active` | неактивный маршрут пропускается (но его резервный маршрут всё равно используется) |

**Входной маршрут** назначения — это активный маршрут, на который не
ссылается как на резервный ни один другой маршрут того же назначения (самый
старый, если таких несколько). От него цепочка идёт по `fallback_route_id`
(циклы обрываются, не более 16 шагов).

### Что переводит на резервный маршрут

| Сбой | Результат |
|---|---|
| отказ в соединении, DNS, тайм-аут | следующий маршрут |
| HTTP 5xx, 429 | следующий маршрут |
| тело ответа не JSON, нет choices | следующий маршрут |
| HTTP 4xx (прочие) | `ProviderRejected`, без перехода на резерв — неверен сам запрос |
| поток оборвался после первой дельты | `ProviderUnavailable`, без перехода на резерв — у вызывающего кода уже есть часть ответа |
| все маршруты отказали | `ProviderUnavailable` (`isTransient() === true`) |

Каждая HTTP-попытка — это строка в журнале вызовов, включая неудачные.

## Протокол

- `POST {base}/chat/completions` с `model`, `messages`, опциями,
  `tools` / `tool_choice`, если заданы, а для структурированного ответа —
  `response_format: {type: json_schema, json_schema: {name, schema, strict: true}}`.
  Потоковый режим добавляет `stream: true` и `stream_options: {include_usage: true}`
  и читает server-sent events.
- `POST {base}/embeddings` с `model` и `input` (список).
- `POST {base}/rerank` с `model`, `query`, `documents`, `top_n` — формат
  Jina/Cohere, который поддерживают vLLM и llama.cpp server. У Ollama и
  LM Studio нет эндпоинта rerank; направляйте `rerank` на сервер, у которого
  он есть.

Вызовы инструментов возвращаются в `LlmResult::$toolCalls` (имя,
декодированные аргументы); пакет не выполняет инструменты и не крутит цикл —
передайте результаты обратно через `history()` и вызовите модель снова.

## Конфигурация (`config/llm.php`)

| Ключ | По умолчанию | |
|---|---|---|
| `http.timeout`, `http.connect_timeout` | 120, 5 | секунды |
| `structured.max_attempts` | 3 | общее число попыток для структурированного ответа |
| `prompts.presets` | `[]` | классы пресетов |
| `log.enabled` | true | |
| `log.keep_bodies_days` | 30 | |
| `log.schedule_prune` | true | ежедневно планировать `llm:prune` |
| `quota.tenant_tokens_per_day`, `quota.project_tokens_per_day` | null | лимиты по умолчанию |
| `attribution.headers` | `X-On-Behalf-Of`, `X-Project`, `X-Task`, `X-Run` | имена заголовков для провайдера с `attribution`; пустое имя не отправляется |
| `effect.attempts` | 3 | должно совпадать с политикой повторов `RunLlm` |
